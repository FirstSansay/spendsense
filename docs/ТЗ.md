# Техническое задание: SpendSense — AI-ассистент для управления личными финансами

---

## 1. Название и описание проекта

**SpendSense** — Telegram-бот для учёта личных финансов. Пользователь фиксирует расходы **без рутины**: текстом, голосовым сообщением или фотографией чека. ИИ автоматически определяет категорию покупки и сумму, бот формирует отчёты по периодам, контролирует бюджет и даёт рекомендации по экономии.

Ценность продукта — это **мотивация к учёту за счёт скорости ввода**: записать трату за 5 секунд проще, чем вести таблицу вручную. Всё происходит прямо в привычном мессенджере, без установки дополнительных приложений.

### Формат
- Telegram-бот на **Python (aiogram 3)**.
- База данных: **SQLite** (MVP) с возможностью перехода на **PostgreSQL**.
- **AI API** для категоризации, распознавания голоса и чека, генерации рекомендаций.

---

## 2. Целевая аудитория и её боли

**ЦА:** люди 18–45 лет, которые хотят контролировать личные финансы, но не ведут учёт регулярно.

Боли целевой аудитории:

| Боль | Как решает SpendSense |
|---|---|
| Забывают записывать расходы | Ввод в один шаг: текст / голос / фото — бот сам разбирает данные |
| Ручная категоризация отнимает время | ИИ автоматически определяет категорию и сумму |
| Непонятно, куда уходят деньги | Отчёты за неделю/месяц с графиками по категориям |
| Слишком сложно вести таблицы в Excel | Учёт прямо в Telegram, без установки приложений |
| Траты выходят за рамки плана | Бюджет на период и контроль превышения |

## 3. Функциональные требования

### 3.1. Обязательное ядро (MVP)

| # | Функция | Описание |
|---|---|---|
| F1 | Регистрация пользователя | Команда `/start`: создание профиля пользователя |
| F2 | Добавление расхода текстом | `/add 250 кофе` → парсинг суммы и описания |
| F3 | ИИ-категоризация | Определение категории (продукты, транспорт, развлечения и т.д.) на основе описания |
| F4 | Отчёт за период | `/report` — сумма и разбивка по категориям за неделю/месяц + график |
| F5 | Бюджет | `/budget 30000` — задать месячный лимит, контроль превышения |
| F6 | История транзакций | Хранение всех операций пользователя в БД |

### 3.2. Ключевые функции второго уровня

| # | Функция | Описание |
|---|---|---|
| F7 | Голосовой ввод | Транскрибация голосового сообщения, извлечение суммы и описания, подтверждение перед сохранением |
| F8 | Распознавание чеков (OCR) | Извлечение покупок из фотографии чека через OCR + ИИ-парсинг |

### 3.3. Расширения (при наличии времени)

| # | Функция | Описание |
|---|---|---|
| F9 | Рекомендации по экономии | ИИ-анализ трат и персонализированные советы |
| F10 | Экспорт данных | Выгрузка в Google Sheets / CSV |

### 3.4. Нефункциональные требования

- **Скорость:** ответ бота на типовой запрос — не более 3 секунд.
- **Надёжность:** устойчивость к некорректному вводу (кривые суммы, пустые сообщения) — без падений.
- **Безопасность:** токены и ключи хранятся только в `.env`, не попадают в репозиторий.
- **Многопользовательность:** данные каждого пользователя изолированы.

## 4. Ограничения и риски

### Ограничения

- **Срок разработки:** 1–2 недели.
- **Бюджет:** затраты на AI API в пределах бесплатного/льготного тарифа.
- **Окружение:** бот работает в Telegram на Python 3.13; OCR требует установленного бинарника `tesseract-ocr`.
- **MVP-границы:** без веб-интерфейса, без мобильного приложения, без авторизации по почте.

### Риски и их снижение

| Риск | Вероятность | Снижение |
|---|---|---|
| Высокая стоимость AI API | Средняя | Оптимизация промптов, кэширование, выбор экономичной модели |
| Низкое качество распознавания речи/чека | Средняя | Подтверждение результата пользователем перед сохранением |
| ИИ ошибается в категории | Средняя | Стандартный набор категорий + возможность правки ответа |
| Не хватает времени на все функции | Высокая | Приоритизация: сначала ядро MVP, затем голос, затем OCR |
| Ошибки в деплое / сбои при запуске | Средняя | Тестирование сценариев до развёртывания, логирование |

---

## 5. Метрики успеха (KPI)

1. **Точность категоризации:** ≥ 90% расходов определяются в правильную категорию.
2. **Скорость ответа:** среднее время обработки запроса — не более 3 секунд.
3. **Стабильность:** безошибочная обработка 30+ транзакций в ходе тестирования (без падений).
4. **Полнота сценариев:** работают все функции ядра MVP (F1–F6) + голосовой ввод (F7).
5. **Деплой:** бот стабильно работает на сервере и отвечает на запросы.

## 7. Приоритизация функционала

**Обязательное ядро (делаем в первую очередь):** регистрация, добавление текстом, ИИ-категоризация, отчёт, бюджет, хранение истории.

**Второй уровень:** голосовой ввод (ключевая фича), OCR чеков.

**Расширения:** рекомендации по экономии, экспорт.

Порядок внедрения: **ядро → голос → OCR → расширения**. Каждый уровень полностью работоспособен и может быть продемонстрирован отдельно.
